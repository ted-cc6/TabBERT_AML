# Portion 3 run plan

Every run Portion 3 owes. Row 47 (`ft_main_seed42_5pct_seed42`) is the reference run
Portion 2 already produced; the other 60 are new. The same matrix is generated by
`python -m Portion3.portion3_baselines plan`, which also shows which rows are already in
`results/runs.csv`. Do not type run ids by hand: the code and this table come from
`Portion3/runplan.py`.

## Groups and rough cost

| Group | Runs | Where | Time |
| --- | --- | --- | --- |
| `rules` | 1 | CPU | under 1 min |
| `if_seed{42,43,44}` | 3 | CPU | 5–10 min each |
| `lgbm_features_*` (5 fractions × 3 seeds) | 15 | CPU | 20–40 min total |
| `lgbm_embeddings_*` main (5 fractions × 3 seeds) | 15 | CPU | 30–60 min total |
| `lgbm_embeddings_abl_*` (2 ablations × 3 seeds at 5%) | 6 | CPU | 2–5 min total |
| `ft_main_*` (5 fractions × 3 seeds, one already done) | 15 | GPU | 1.5–2 h |
| `ft_abl_*` (2 ablations × 3 seeds at 5%) | 6 | GPU | 40–60 min |
| **Total new** | **60** | | **≈ 3.5 h compute** |

Plus one-time costs: 26 GB embedding download (or 13 GB via the Colab slice), 5–10 min
setup, 30 s data load per command.

## Order

1. Verify (`pytest`, `plan`, `prepare_embeddings check`).
2. `rules` → `isolation-forest` → `lightgbm` (core RQ1 baseline, no embeddings needed).
3. Download/slice embeddings; `tune`; update `configs/lightgbm.json`.
4. `lightgbm-embeddings`.
5. `run_finetune.py` on the GPU (20 runs).
6. `score-finetune` to add the fine-tune rows to the log.
7. `summary`; commit `results/runs.csv`.
